## 2. Metal RoPE / YaRN Scaling Implementation Details

### 2.1 The Issue in Upstream v0.2.1
Upstream `v0.2.1` (`Strata-0.2.1/metal/src/engine/window.cpp:491–497`) removed `RopeScaling` and hardcoded plain exponential frequency tables:

```cpp
// UPSTREAM REGRESSION IN v0.2.1 (DO NOT USE)
const double base = f_.meta_num.count("qwen4exp.rope.freq_base") ? f_.meta_num["qwen4exp.rope.freq_base"] : 1e7;
for (int p = 0; p < MAXC + 16; ++p)
    for (int i = 0; i < 32; ++i) {
        const double th = (double) p * std::pow(base, -2.0 * i / 64.0);
        cs_.as<float>()[(p * 32 + i) * 2] = (float) std::cos(th);
        cs_.as<float>()[(p * 32 + i) * 2 + 1] = (float) std::sin(th);
    }
```

This caused context degradation and immediate attention breakdown when context token counts exceeded 32,768 tokens.

### 2.2 Preserved Integration in `v0.2.1-m5`

In `v0.2.1-m5`, we preserve `RopeScaling` dispatch and interleaved trigonometric table generation via `metal/src/engine/rope_table.h` and `metal/src/engine/window.cpp`.

#### Host-Side Table Generation Math (`metal/src/engine/rope_table.h`):
```cpp
namespace strata::metal_engine::detail {

template <class Writer>
inline void rope_table(int n_rot, const strata::kernels::RopeScaling& sc, int max_pos, Writer&& w) {
    const int half = n_rot / 2;
    std::vector<double> inv((size_t) half);
    for (int i = 0; i < half; ++i) inv[(size_t) i] = std::pow(sc.freq_base, -2.0 * (double) i / (double) n_rot);

    if (sc.type == strata::kernels::RopeScalingType::None) {
        for (int p = 0; p < max_pos; ++p)
            for (int i = 0; i < half; ++i) {
                const double ang = (double) p * inv[(size_t) i];
                w(p, i, (float) std::cos(ang), (float) std::sin(ang));
            }
        return;
    }

    const double fs = sc.freq_scale();
    const double ms = sc.mscale();
    double cd[2];
    sc.corr_dims(n_rot, cd);
    const bool correct = sc.ext_factor != 0;
    for (int p = 0; p < max_pos; ++p)
        for (int i = 0; i < half; ++i) {
            const double extrap = (double) p * inv[(size_t) i];
            const double interp = fs * extrap;
            double ang = interp;
            if (correct) {
                const double ramp = (double) strata::kernels::rope_yarn_ramp((float) cd[0], (float) cd[1], i) * sc.ext_factor;
                ang = interp * (1.0 - ramp) + extrap * ramp;
            }
            w(p, i, (float) (std::cos(ang) * ms), (float) (std::sin(ang) * ms));
        }
}

} // namespace strata::metal_engine::detail
```

#### Window Initialization Dispatch (`metal/src/engine/window.cpp`):
```cpp
// Interleaved float2 [pos][32] table built at runtime initialization
strata::kernels::RopeScaling sc = strata::kernels::rope_scaling();
if (sc.freq_base <= 1.0) {
    sc.freq_base = f_.meta_num.count("qwen4exp.rope.freq_base") ? f_.meta_num["qwen4exp.rope.freq_base"] : 1e7;
}
build_rope_table_interleaved(64, sc, MAXC + 16, cs_.as<float>());
if (sc.type != strata::kernels::RopeScalingType::None) {
    std::fprintf(stderr, "strata metal: RoPE scaling %s active on Metal decode window (factor %.6g, mscale %.6f)\n",
                 sc.type == strata::kernels::RopeScalingType::YaRN ? "yarn" : "linear", sc.factor, sc.mscale());
}
```

#### Metal Shader Execution (`metal/kernels/qsa.metal`):
The host buffer `cs_` is bound to the Metal pipeline. `qsa.metal` reads precomputed `float2` pairs directly during the query-key attention pass:

```metal
// qsa.metal: Metal attention kernel applying precomputed RoPE pair
float2 cs = cs_tab[pos * 32 + (head_dim_idx / 2)];
float q_rot = q.x * cs.x - q.y * cs.y;
float k_rot = k.x * cs.x - k.y * cs.y;
```

## 3. Swift 1.5 Compatibility Architecture

### 3.1 Model Identification & Family Mapping
"Swift 1.5" refers to UkisAI's fine-tune series (`Swift-1.5-Qwen3.8-Flash-Next-GSQ-RCO-GGUF`).
In `metal/setup_mac.py`:
- Registered under `family = "swift"`.
- GGUF architecture metadata: `general.architecture = "qwen4exp"`.
- Tensor hidden dimension: 2,560; Layers: 48; Mixture-of-Experts routing.

### 3.2 Quantization & Sharding Support Matrix

| Quantization Variant | Shard 1 File Size | Multi-Shard Status | Metal Execution |
|---|---|---|---|
| **`IQ2_XS`** | ~39.8 GB | Supported | Full GPU Execution |
| **`IQ3_XXS`** | ~39.8 GB | Supported | Full GPU Execution |
| **`IQ3_S`** | ~44.9 GB | Supported | Full GPU Execution |
| **`Q2_0`** | ~37.6 GB | **Excluded** | Excluded in `setup.py` / `setup_mac.py` due to expert layer splitting across GGUF shards. |

### 3.3 Exclusion Guard (`setup.py` & `metal/setup_mac.py`):
```python
if a.family == "swift" and a.model == "Q2_0":
    S.fail("Swift 1.5's Q2_0 files split one layer's experts across the two shards, which the pack tool (tools/iq_pack.py) cannot prepare yet (#171)")
```
