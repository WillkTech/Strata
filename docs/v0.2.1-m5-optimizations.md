## 2. Dynamic Unified-Memory Arena Budgeting (`arena_budget.h`)

### 2.1 The macOS System Panic Prevention Rule
On Apple Silicon unified memory, a single process holding an excessively large footprint can trigger macOS system watchdog panics or force swap compression.

In `metal/src/engine/arena_budget.h`, `arena_keep()` dynamically computes the RAM buffer reserved for macOS system stability:

$$\text{keep\_bytes} = \max(7.0\text{ GB}, 0.15 \times \text{RAM})$$

For a 128 GB M5 Max:
$$\text{keep} = \max(7.0, 0.15 \times 128) = 19.2\text{ GB}$$

This automatically caps the engine resident working set at:
$$128.0 - 19.2 = 108.8\text{ GB}$$

### 2.2 Anonymous Footprint vs. RSS Tracking
Apple Silicon unified memory tracking differentiates anonymous process footprint from total resident set size using macOS `TASK_VM_INFO`:

```cpp
// metal/src/engine/arena_budget.h
inline PhysMem phys_mem() {
    task_vm_info_data_t ti;
    mach_msg_type_number_t count = TASK_VM_INFO_COUNT;
    if (task_info(mach_task_self(), TASK_VM_INFO, (task_info_t)&ti, &count) == KERN_SUCCESS) {
        return { (uint64_t) ti.phys_footprint, (uint64_t) ti.resident_size };
    }
    return { 0, 0 };
}
```

## 3. Apple Silicon Mach VM Host Memory Sampling

In non-Metal host memory tracking (`src/core/conversation_memory.cpp`), Apple Silicon Mach host statistics are sampled using `sysctlbyname("hw.memsize")` and `host_statistics64`:

```cpp
// src/core/conversation_memory.cpp
#elif defined(__APPLE__)
    uint64_t phys = 0;
    size_t len = sizeof phys;
    if (sysctlbyname("hw.memsize", &phys, &len, nullptr, 0) != 0 || phys == 0) return {};
    vm_statistics64_data_t vs;
    mach_msg_type_number_t cnt = HOST_VM_INFO64_COUNT;
    if (host_statistics64(mach_host_self(), HOST_VM_INFO64, (host_info64_t)&vs, &cnt) != KERN_SUCCESS) return {};
    const double pg = (double) vm_page_size;
    const double free_b = vs.free_count * pg;
    const double purge_b = vs.purgeable_count * pg;
    const double inact_b = vs.inactive_count * pg;
    const double spec_b = vs.speculative_count * pg;
    const double ext_b = vs.external_page_count * pg;

    // Available RAM matching Metal arena availability:
    const double avail_b = free_b + purge_b + std::min(inact_b + spec_b, ext_b);
    return combine((uint64_t) avail_b, phys, CgroupScan{}, memory_limit_bytes());
```

## 4. M5 Max Metal SIMDgroup & Constant Memory Table Tuning

### 4.1 SIMD Matrix Tile Layout Selection (`coop_probe.h`)
Metal matrix multiplication kernels (`metal/kernels/moe.metal`, `gemv.metal`, `qsa.metal`) select tile dimensions based on dynamic SIMDgroup probing:

- `coop_k4()` detects the M5 Max SIMD matrix layout (`m5_layout = 1`).
- Dynamically selects 32x32 and 64x64 SIMD tile dimensions optimized for M5 Max execution units.

### 4.2 Quantization Table Constant Memory (`QUANT_CTAB`)
In `metal/src/engine/window.cpp`, function constant 23 (`QUANT_CTAB`) preloads quantization scale tables directly into MSL constant memory, yielding a 3%–7% speedup during MoE matrix-vector multiplications on Metal.

## 5. Subprocess Supervision & Unified Memory Leak Prevention

### 5.1 Lifeline Process Anchor (`serve/lifeline.py`)
To prevent orphaned Metal C++ processes from holding onto 100+ GB of unified memory when the Python server restarts or exits:
- Uses `serve/lifeline.py` to bind child C++ process life cycles directly to parent process handles.
- On macOS, a lightweight pipe watcher detects parent death and immediately issues `SIGTERM` / `SIGKILL` to the C++ engine process.

## 6. Recommended Hardware Configuration for M5 Max 128 GB

For a future agent configuring default settings for 128 GB Apple Silicon M5 Max:

- **Context Length:** 65,536 tokens (`--max-context 65536`).
- **Speculative Draft Layer:** Enabled (`--spec 2` or `--spec 3`).
- **RAM Reserved for macOS:** 19.2 GB (`STRATA_METAL_KEEP_FREE_GB=19.2`).
- **Quantization:** `IQ3_S` or `UD-Q4_K_XL` (for Unsloth repacked models).
